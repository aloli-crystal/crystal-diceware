== v0.1.4 — 2026-04-29

**Repo GitHub renommé** `aloli-crystal/crystal-diceware` →
`aloli-crystal/diceware` (convention de nommage Aloli : les créations
originales abandonnent le préfixe `crystal-`). Les anciens liens
redirigent automatiquement.

* Champ `name:` du `shard.yml` mis à jour de `crystal-diceware` à `diceware`.
* **Cible de compilation renommée** `crystal-diceware` → `diceware` :
  la commande devient `shards build diceware` et produit `bin/diceware`.
  Les invocations CLI documentées passent de `crystal-diceware ...` à
  `diceware ...`. La nouvelle convention de l'écosystème supprime le
  préfixe `crystal-` aussi sur les binaires.
* README et exemples mis à jour.

== v0.1.3 — 2026-04-28

**Renommage des fichiers source pour aligner sur le nom du module.**
Le module s'appelle `Diceware` (depuis v0.1.1) ; le fichier
d'entrée et son dossier de modules portent désormais le même nom.

* `src/crystal_diceware.cr` → `src/diceware.cr`
* `src/crystal_diceware/` → `src/diceware/`
* Les `require` internes et `spec/spec_helper.cr` sont adaptés.

**Impact pour les utilisateurs** : le `require` côté consommateur
passe de `crystal-diceware/crystal_diceware` à
`crystal-diceware/diceware`. Le nom du shard (`crystal-diceware`,
convention paquet Aloli) reste inchangé.

== v0.1.2 — 2026-04-28

**Nettoyage CLI : tous les drapeaux long ont un short, séparation
nette commandes/options, sous-commande `help` enrichie.**

=== Changements

* **Nouveau short `-D`** pour `--dice` (mode manuel). Toutes les
  options long ont désormais un short.
* **Sous-commande `version` retirée** — doublonnait le drapeau
  Unix standard `-v` / `--version`.
* **Sous-commande `help` conservée et enrichie** — accepte
  désormais un argument optionnel pour afficher la documentation
  détaillée d'une sous-commande spécifique (style `git help`).

=== Doc détaillée par sous-commande

[source,shell]
----
crystal-diceware help              # résumé général (= --help)
crystal-diceware help generate     # NAME / USAGE / OPTIONS / EXEMPLES
crystal-diceware help roll
crystal-diceware help lookup
crystal-diceware help list
crystal-diceware h g               # alias courts utilisables
----

Chaque page de doc liste les options pertinentes et 3-5 exemples
concrets. Plus utile que la bannière commune trop large.

=== Récap des shorts

[cols="1,1,3"]
|===
| Long | Short | Description

| `--words`        | `-n` | Nombre de mots (défaut : 7)
| `--language`     | `-l` | Wordlist
| `--dice`         | `-D` | Mode manuel (NOUVEAU short)
| `--auto-words`   | `-k` | Mode hybride
| `--separator`    | `-s` | Séparateur
| `--entropy`      | `-e` | Affiche l'entropie
| `--version`      | `-v` | Version
| `--help`         | `-h` | Aide
|===

== v0.1.0 — 2026-04-28

Première version publique. Générateur de passphrases Diceware
en Crystal pur.

=== Fonctionnalités

* **Trois sources d'aléa** :
** `:auto` (défaut) — `Random::Secure` (`/dev/urandom`)
** `:manual` — jets de dés fournis par l'utilisateur (héritage
   du Diceware physique)
** `:hybrid` — K mots auto + (N-K) manuels

* **Deux wordlists embarquées** :
** `eff_long` (anglais, 7776, référence EFF 2016)
** `fr_mbelivo_5d` (français, 7776, mbelivo / dérivé Lexique)

* **API Crystal** :
** `Diceware.generate(words:, language:, source:, rolls:, auto_words:, separator:)`
** `Diceware.roll(words:, source:, rolls:, auto_words:)`
** `Diceware.entropy(words:, wordlist:)`
** `Diceware::Wordlist` (`.for`, `.identifiers`,
   `.languages`, `.default`, `#size`, `#lookup`, `#secure_word`)
** `Diceware::Roll` (`.from_string`, `.from_index`,
   `.secure`, `#to_index`, `#to_s`, `#digits`)

* **CLI** avec alias courts :
** `generate` (`g`) | `roll` (`r`) | `lookup` (`lk`) |
   `list` (`ls`) | `version` (`v`) | `help` (`h`)

=== Tests

40 exemples verts (dont 2 tests statistiques χ² d'uniformité
sur 1 M tirages chacun, lançables via
`crystal spec --tag statistical`). Les vecteurs sont validés
contre les références EFF publiées (`11111` → `abacus`,
`66666` → `zoom`, plus un échantillon représentatif).

=== Embarquement

Les wordlists sont compilées dans le binaire via
`{{ read_file(...) }}` (zéro chargement à l'exécution, zéro
dépendance externe). Chaque langue ajoute ~50 Ko au binaire.
